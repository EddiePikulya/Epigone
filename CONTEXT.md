# Epigone — Domain Glossary

> Ubiquitous language for the Epigone project. Glossary only — no implementation details.

| Term | Definition |
| --- | --- |
| **Epigone** | A Telegram bot that finds and tracks the best Hyperliquid perp traders and prediction-market traders, where "best" is defined by each user's own criteria — there is no single global leaderboard. Named after "epigone" (imitator of the greats): the product's thesis is *cloning the best to be the best*. |
| **Criteria** | A user-defined definition of "best trader": a set of filters over the Metric Library plus a sort key (screener-style). Each user can have their own; the same trader can rank #1 for one user and be invisible to another. |
| **Metric Library** | The fixed set of per-Trader metrics Epigone computes (e.g. PnL, win rate, Sharpe, max drawdown, trade count, account age, average leverage — exact list to be specified) over defined timeframes. Criteria are expressed exclusively in terms of these metrics. |
| **Trader** | An externally observable market participant (e.g. a Hyperliquid account / prediction-market wallet) that Epigone evaluates and tracks. Not a user of the bot. |
| **User** | A person interacting with Epigone through Telegram. Open to anyone with a Telegram account. |
| **Universe** | The full set of candidate Traders Epigone knows about and scores (initially discovered from open Hyperliquid leaderboard stats; ~40k active accounts as of July 2026). Criteria filter the Universe; Users track Traders from it. |
| **Bot (excluded Trader)** | An account whose statistical profile indicates automated market-making rather than copyable trading skill (e.g. ~100% win rate over hundreds of exits, extreme fill frequency, or PnL from static holdings). Excluded from the Universe during vetting. |
| **Track** | A User's explicit, manual follow of a specific Trader (chosen from screener results or entered directly). Tracking is a stable User→Trader relationship; Criteria never add or remove tracked Traders on their own. |
| **Position Alert** | A realtime Telegram notification pushed to a User when a Trader they track opens, closes, or flips a position. The unit of value of the tracking half of the product. |
| **Order Event** | A change Epigone observed to one of a Trader's resting orders — *placed*, *filled*, *canceled*, *rejected*, *triggered*, *gone* or *other* — recorded durably as the thing that happened to that order, keyed by the exchange's order id. (*canceled* is spelled the exchange's way, because the exchange's own word for the change is kept beside Epigone's.) Distinct from a Position Event: an order is a Trader's *plan*, a position is what the plan did. A modify is not one event but two, a cancel and a place, because that is what the exchange does. An order that left the book while Epigone was not watching is *gone* — known to have ended, not known how; a change the exchange describes in a word Epigone's vocabulary does not recognise is *other*, carrying that word rather than a guess. |
| **Position Event** | A change Epigone observed in a Trader's position — an open, close, flip, scale-in or scale-out — recorded durably as the thing that happened, independently of whether any User was notified about it. A Position Alert is one reader of it; copy execution is another. A flip is a single event carrying both legs, never a close followed by an open. Positions that predate Epigone's first look at a Trader are not events: nobody could have seen them open. |
| **Withdrawal Alert** | A realtime Telegram notification pushed to every User tracking a Trader when that Trader's Account Equity falls by more than the same interval's PnL accounts for — money leaving the account rather than a trade going against them. Inferred, never observed: Epigone sees what the account was worth at two instants and what it held at those instants, and calls the unexplained difference an outflow, so funding and fees ride inside the figure and thresholds absorb them. A losing Trader is not a leaving Trader, which is the whole distinction the alert exists to draw. |
| **Account Equity** | What a Trader's account is worth on the venues Epigone watches — their margin, unrealized PnL and idle collateral, summed across those venues, since each holds its own collateral. Not an event but an observation: it is what was true when Epigone last looked, re-observed every poll pass whether or not it changed, so only the newest is kept. Deliberately a partial view of the wallet — a venue Epigone does not poll, or a spot balance, is outside it — because it is the money backing the positions Epigone actually diffs. |
| **Leader** | A Trader the operator has explicitly enabled for copy execution. Copying is a subset of tracking: every Leader is tracked, but tracking alone never makes a Leader — the flag is explicit and defaults off. |
| **Copy Sub-account** | A Hyperliquid sub-account the operator funds with a fixed allocation and assigns exactly one Leader to. Its balance is the hard, exchange-enforced exposure cap for that Leader; its trading history is the Leader's copy performance record. Losses in one Copy Sub-account cannot touch another's allocation. (Hosting several Leaders in one sub is deliberately deferred: it reintroduces same-coin ownership questions that single-Leader subs dissolve.) |
| **Base Stake** | The fixed dollar amount of the Operator's own collateral committed to each copied open, configured per Copy Sub-account. (Supersedes *Base Notional*, which fixed position size instead.) The copy's position size is Base Stake × the mirrored leverage, so a $100 stake behind a 10x Leader is a $1,000 position — exposure follows the Leader's conviction; the money at risk stays the Operator's constant. A Leader's absolute position size still never enters; only their leverage, and their subsequent relative changes (a 50% scale-in scales the copy by 50%). Each position's margin is isolated, so the stake is also the worst case: one position's loss can never eat the rest of the allocation. |
| **Mirrored Leverage** | The leverage a copied open runs at: the Leader's own leverage on that position, capped by the Operator's leverage limit — whichever is lower. Mirroring is what makes Base Stake meaningful (the Leader's conviction scales the exposure); the cap is what keeps the Leader's leverage dial from becoming an attack surface (notional, and everything that scales with it, is stake × leverage). |
| **Copyable Coin** | A coin the risk policy permits copy execution to trade: any coin whose live market clears the Liquidity Floor. Deliberately not a curated list — which coins to trade is the Leader's decision; Epigone's only veto is market health. (Unrelated to the Telegram invite allowlist, which gates Users, not coins.) |
| **Liquidity Floor** | The minimum live-market health a coin must show to be a Copyable Coin, judged against the market as it is now, not as it once was. An anti-extraction tripwire, not a coin preference: thin books are where a copied trade's counterparty can be the Leader themselves. Operator-tunable, including off — the floor is a default stance, not a cage. The floor speaks exactly once per Copy Episode, at the open that starts it: a live episode is never interrupted by it (scale-ins copy even after the coin goes thin) and never trapped by it (exits always sign). A flip ends the episode, so a flip's opening leg is a fresh entry and the floor speaks again. |
| **Copy Mode** | A per-Copy-Sub-account exit policy. `default`: pure copy — positions exit when the Leader exits. `bracket`: the sub wraps each position in its own TP/SL trigger percentages, applied at fill time, overriding the Leader's exit timing. `mirror` (future): copy the Leader's actual TP/SL orders — requires the websocket order seam. |
| **Copy Episode** | One position's life in a Copy Sub-account, from copied open to whatever ends it (Leader exit, bracket trigger, or operator action). Once ended, later Leader events on that same position are skipped until the Leader fully closes and freshly re-opens — a bracket exit is a local decision, not a pause. |
| **Operator** | The single User who owns the master wallet and administers Epigone's execution (Phase A: exactly one). Copy commands answer only the Operator; other Users can track and receive alerts but cannot copy. |
